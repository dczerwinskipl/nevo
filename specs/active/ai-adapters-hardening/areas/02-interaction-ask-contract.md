# Area: Interaction and Ask contract

## Purpose

Define the unified provider-neutral interaction contract for mid-turn user input (questions, permissions, confirmations), ensuring consistent correlation, resumption policies, and lifecycle behavior across disparate provider transports.

## Interaction kinds & schemas

The canonical model defines three distinct interaction kinds:

### 1. `question`
Used when the agent requires user clarification or selections to proceed.
- **Request payload**:
  - `id`: Unique interaction ID (`int-<uuid>`).
  - `resumePolicy`: `'restart' | 'live-operation'`.
  - `questions`: Array of 1 to 20 question objects:
    - `id`: Stable question ID unique within the interaction (`q-<uuid>`).
    - `question`: Non-empty string prompt (up to 1,000 chars).
    - `header`: Optional short category header (up to 100 chars).
    - `options`: Optional array of up to 20 selectable options:
      - `label`: Non-empty label (up to 200 chars).
      - `description`: Optional explanatory detail (up to 500 chars).
    - `multiSelect`: Boolean flag (true = checkboxes, false = single choice / radio).
- **Response payload**:
  - `answers`: Exactly one answer per question ID:
    - `questionId`: Must correlate to an existing question ID.
    - `value`: String (for single select / freeform) or string array (for multi-select).

### 2. `permission`
Used when the agent requests authorization to execute a sensitive or mutating operation (file edit, terminal command, network fetch).
- **Request payload**:
  - `id`: Unique interaction ID (`int-<uuid>`).
  - `resumePolicy`: `'restart' | 'live-operation'`.
  - `toolName`: Name of the tool requesting approval (up to 100 chars).
  - `input`: Bounded normalized JSON object representing the proposed tool arguments (up to 4,096 chars encoded; no provider-private fields).
  - `details`: Optional human-readable description of the security impact (up to 2,000 chars).
- **Response payload**:
  - `decision`: `'allow' | 'deny'`.
  - `message`: Optional user explanation (up to 1,000 chars).

### 3. `confirmation`
Used when the agent seeks high-level acknowledgment of a non-tool plan or irreversible workflow phase.
- **Request payload**:
  - `id`: Unique interaction ID.
  - `resumePolicy`: `'restart' | 'live-operation'`.
  - `title`: Short title (up to 200 chars).
  - `message`: Descriptive prompt (up to 2,000 chars).
  - `details`: Optional technical detail.
  - `payload`: Optional structured data.
- **Response payload**:
  - `confirmed`: Boolean flag.
  - `decision`: `'confirm' | 'cancel'`.
  - `message`: Optional explanation.

## Correlation & continuation semantics

1. **Correlation IDs**:
   - Every interaction request carries an immutable neutral `interaction.id` generated by the runtime or adapter.
   - Provider-private IDs (e.g. Codex app-server JSON-RPC request IDs, Claude MCP request IDs) are held strictly inside the adapter correlation map (`#interactions` in Codex, `mcpInteractionRegistry` in Claude).
   - Responses from the browser reference only the neutral `interaction.id`. The adapter looks up the private request handle, sends the provider protocol response, and releases the handle.

2. **Continuation in the same logical Turn**:
   - Resolving an interaction does NOT start a new Turn. The active Turn continues execution under the same `turnId`.
   - The interaction WorkItem status transitions from `pending` to `resolved` (or `denied`/`rejected`).
   - Turn status transitions from `requiresAttention` back to `active (detail: 'processing')`.

3. **Resume policy & server restart**:
   - `resumePolicy: 'live-operation'`: The interaction depends on an active, in-memory provider transport connection (e.g. Codex stdio request or Claude live MCP call). If the server restarts while this interaction is pending, the provider connection is broken. Boot reconciliation must terminate the interaction as `interrupted` and seal the Turn as `terminal (outcome: 'interrupted', cause: 'server-restart')`.
   - `resumePolicy: 'restart'`: The interaction can be reconstructed after server restart by spawning a fresh provider command with saved continuation state (e.g., legacy Claude deferral). Stored in `.nevo-ai-local/transcripts/`.

4. **Cancellation while interaction is pending**:
   - If a user cancels a Turn while an interaction is pending, `TurnLifecycleCoordinator` immediately transitions the turn status to `cancelling`, transitions the interaction WorkItem to `status: 'cancelled'`, and invokes adapter `cancelTurn()`.
   - Codex adapter cancels the underlying pending JSON-RPC request with a declining response. Claude adapter cancels via `mcpInteractionRegistry.cancelTurn()`.

5. **Unsupported capabilities**:
   - If an interaction is submitted to an adapter that does not support it (e.g., Antigravity `respondInteraction()`), the adapter must fail fast by throwing `CapabilityNotSupportedError(provider, capability)`.
   - The UI inspects `descriptor.capabilities.interactiveQuestions` and `interactivePermissions` to hide or disable interactive triggers.
