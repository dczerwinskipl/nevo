# Area: Interaction and Ask contract

## Purpose

Define the provider-neutral interaction contract for mid-turn user input (questions, permissions, confirmations), ensuring consistent correlation, resumption policies, and lifecycle behavior across disparate provider transports.

---

## 1. Interaction kinds and schemas

### Current fact
- The canonical contract in `tools/dashboard/server/ai/contracts.mjs` (`normalizeInteraction`) defines three interaction kinds: `question`, `permission`, and `confirmation`.
- `INTERACTION_RESUME_POLICIES` defines two policies: `'restart'` and `'live-operation'`.
- Codex natively supports `question` and `permission` via JSON-RPC. Claude supports `question` via MCP HTTP bridge.
- Antigravity operates headlessly in print mode (`agy --print <prompt> --output-format stream-json`). Live probe verification confirms it connects to configured MCP servers and invokes MCP tools. Antigravity uses machine-global MCP configuration managed through `agy mcp add|list|remove`. Live probes confirm `agy` does not interpolate environment variables in configured HTTP headers or `serverUrl`, and direct HTTP requests contain no turn correlation. However, stdio MCP subprocesses spawned by `agy` inherit `process.env`. Nevo integrates with Antigravity via a durable, idempotently managed stdio bridge script (`antigravity-mcp-bridge.mjs`) registered under server name `nevo`, which forwards stdio JSON-RPC to the shared loopback Fastify `/mcp` route attaching the turn-scoped `x-nevo-interaction-token`.

### Proposed target
Retain the three structured interaction kinds:

#### 1. `question`
Used when the agent requires user clarification or selections to proceed.
- **Request payload**:
  - `id`: Unique interaction ID (`int-<uuid>`).
  - `resumePolicy`: `'restart' | 'live-operation'`.
  - `questions`: Array of 1 to 20 question objects:
    - `id`: Stable question ID unique within the interaction (`q-<uuid>`).
    - `question`: Non-empty string prompt (up to 1,000 chars).
    - `header`: Optional short category header (up to 100 chars).
    - `options`: Optional array of up to 20 selectable options (`label`, optional `description`).
    - `multiSelect`: Boolean flag (true = checkboxes, false = radio/single-choice).
- **Response payload**:
  - `answers`: Array of answers correlating by `questionId` with string or string array `value`.

#### 2. `permission`
Used when the agent requests authorization to execute a sensitive or mutating operation (file edit, terminal command, network fetch).
- **Request payload**:
  - `id`: Unique interaction ID.
  - `resumePolicy`: `'restart' | 'live-operation'`.
  - `toolName`: Name of the tool requesting approval (up to 100 chars).
  - `input`: Bounded normalized JSON object representing the proposed tool arguments (up to 4,096 chars encoded; no provider-private fields).
  - `details`: Optional human-readable description of security impact (up to 2,000 chars).
- **Response payload**:
  - `decision`: `'allow' | 'deny'`.
  - `message`: Optional user explanation (up to 1,000 chars).

#### 3. `confirmation`
Used when the agent seeks high-level acknowledgment of a plan or irreversible workflow phase.
- **Request payload**:
  - `id`: Unique interaction ID.
  - `resumePolicy`: `'restart' | 'live-operation'`.
  - `title`: Short title (up to 200 chars).
  - `message`: Descriptive prompt (up to 2,000 chars).
  - `details`: Optional technical detail.
- **Response payload**:
  - `confirmed`: Boolean flag.
  - `decision`: `'confirm' | 'cancel'`.
  - `message`: Optional explanation.

### Owner decision resolution
- **Adopted (Approved by Owner — Decision 3)**: Retain the three neutral structured interaction kinds (`question`, `permission`, `confirmation`). Provider adapters map their native interaction mechanisms into these neutral schemas without exposing transport artifacts.

## 2. Correlation and continuation semantics

### Current fact
- Interactions occur inside an active turn; resolving an interaction does not create a new turn.
- In `turn-recovery.mjs` (`reconcileOrphanedTurns`):
  - Pending interactions with `resumePolicy === 'live-operation'` are authoritatively interrupted upon server restart because their live provider socket/process correlation was lost.
  - Pending interactions with `resumePolicy === 'restart'` are left untouched and can be answered across restarts.

### Target architecture
1. **Correlation IDs**:
   - Every interaction request carries an immutable neutral `interaction.id` generated by the runtime or adapter.
   - Provider-private IDs (e.g. Codex app-server JSON-RPC request IDs, Claude MCP request IDs) remain strictly inside the adapter correlation map.
   - Responses from the browser reference only the neutral `interaction.id`. The adapter looks up the private request handle, sends the provider protocol response, and releases the handle.

2. **Continuation in the same logical Turn**:
   - Resolving an interaction does NOT start a new Turn. The active Turn continues execution under the same `turnId`.
   - The interaction WorkItem status transitions from `pending` to `resolved` (or `denied`/`rejected`).
   - Turn status transitions from `requiresAttention` back to `active (detail: 'processing')`.

3. **Resume policy & server restart**:
   - `resumePolicy: 'live-operation'`: The interaction depends on an active, in-memory provider transport connection (e.g. Codex stdio request or Claude live MCP call). If the server restarts ungracefully while this interaction is pending, the provider connection is broken. Boot reconciliation marks the interaction as `interrupted` and seals the Turn as `terminal (outcome: 'interrupted', cause: 'server-restart')`.
   - `resumePolicy: 'restart'`: The interaction can be reconstructed after server restart by spawning a fresh provider command with saved continuation state.

4. **Cancellation while interaction is pending**:
   - If a user cancels a Turn while an interaction is pending, `TurnLifecycleCoordinator` immediately transitions the turn status to `cancelling`, transitions the interaction WorkItem to `status: 'cancelled'`, and invokes adapter `cancelTurn()`.
   - Codex adapter cancels the underlying pending JSON-RPC request with a declining response. Claude and Antigravity adapters cancel pending MCP interactions via `mcpInteractionRegistry.cancelTurn()`.

5. **Terminal textual questions (Composer fallback)**:
   - When an interactive provider model outputs a question in conversational text without triggering a structured tool interaction:
   - The turn completes normally with `status: 'terminal' (outcome: 'completed')` and the question text resides in `finalAnswer`.
   - The user replies using the normal composer, initiating a new turn.
   - No synthetic interaction is fabricated via text regex.

### Owner decision resolution
- **Adopted across all three providers (Approved by Owner — Decision 3)**:
  - All three providers expose structured question interactions (`interactiveQuestions: true`):
    - **Codex**: Native stdio JSON-RPC.
    - **Claude**: In-process Fastify MCP bridge (`/mcp`) configured via `--mcp-config`.
    - **Antigravity**: Loopback Fastify MCP bridge (`/mcp`) via durable stdio bridge script (`antigravity-mcp-bridge.mjs`) registered with `agy`.
  - Durable Antigravity stdio MCP integration:
    - Avoids fragile startup-add/shutdown-remove lifecycle; registered once in `~/.gemini/config/mcp_config.json` via `agy mcp add nevo node "<path-to-bridge>"`.
    - Uses deterministic server identity: `nevo`.
    - `AntigravityAgentProvider` spawns `agy` with `NEVO_INTERACTION_TOKEN` and `NEVO_MCP_ENDPOINT` in the child environment block.
    - When `agy` connects to MCP, it spawns `node antigravity-mcp-bridge.mjs`, which inherits the token and endpoint, connects to the Fastify `/mcp` HTTP endpoint, and attaches `x-nevo-interaction-token: <NEVO_INTERACTION_TOKEN>`.
    - Concurrency isolation: each turn has its own process tree and isolated environment block; concurrent turns never leak or cross-correlate tokens.
    - Strict turn binding: Fastify `/mcp` validates the token against `mcpInteractionRegistry.getActiveTurnByToken(token)`. When a turn terminates, its token is unbound; stale requests receive HTTP 403 Forbidden.
    - Safe isolation: never touches unrelated user MCP servers. If `agy` is run outside Nevo, the bridge detects missing token and exits cleanly without exposing tools.
  - Composer fallback is retained as a fallback for ordinary conversational questions at turn end that did not invoke the structured `ask_user` tool.
  - Zero text heuristics: no regex pattern matching to fabricate interactions from final text.
