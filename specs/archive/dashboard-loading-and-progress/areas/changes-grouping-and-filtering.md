# Area: Changes grouping and filtering

## Responsibility

Make the Changes view change/spec-centric instead of an unordered flat list: configurable,
deterministic grouping (Area/Directory/Flat), generated-file/lockfile/noise detection as
a filter dimension (not a group), and make background diff hydration respect whichever
files are currently hidden.

## Current state

- `changes-panel.tsx`'s `PullRequestCard` renders `pullRequest.files.map(...)` as a flat
  list (lines 227-237) in GitHub's return order; the only existing heuristic is
  `collapseFilesInitially = files.length > 50` (line 163), which only changes default
  open/closed state, not order or grouping.
- No `.gitattributes` exists in the repo; no glob-matching library is a direct
  dependency of `tools/dashboard` or the root `package.json` today (`picomatch` appears
  only transitively in `tools/dashboard/package-lock.json`) — see D1 in
  `owner-decisions.md`.
- No generated-file, lockfile, or noise detection exists anywhere in the dashboard.

## Requirements

- A per-project config (exact file location/format is an implementation detail —
  natural fit is alongside other NEvo project config) defines `changeView.groups`: an
  ordered list of `{ name, paths: [glob...] }` rules, first-match-wins, with a
  `fallback: true` catch-all group (e.g. "Other"). Do not hardcode NEvo's own directory
  structure as a universal default beyond a reasonable out-of-the-box config that this
  repo itself uses.
- Path matching uses `picomatch` (D1) against each file's path from the manifest built
  in `pull-request-file-and-diff-loading.md`.
- Group-by modes: **Area** (uses `changeView.groups`), **Directory** (natural repo
  structure), **Flat** (current flat list, kept as an option).
- A separate `generatedFiles` config (same glob-rule shape) marks files as generated;
  generated is a filter dimension ("Hide generated files"), not a top-level group — a
  generated file still belongs to whatever group (Source, Tests, ...) it would
  otherwise match. An optional fallback heuristic (`// <auto-generated />` marker) may
  supplement explicit path rules, but explicit config rules take precedence.
- Lockfiles are tracked as their own concept, not automatically folded into "generated".
- The UI can show a visible/generated-hidden count (e.g. "84 files changed · 31 visible
  · 53 generated hidden") and let the user un-hide generated files easily — hiding must
  never be a one-way filter.
- When generated (or otherwise explicitly hidden) files are hidden, background diff
  hydration (from `pull-request-file-and-diff-loading.md`) skips them; opening/showing a
  hidden file triggers its fetch at that point, same priority rules as any user-opened
  file.
- No AI-based classification anywhere in this area — deterministic glob rules only.
- Since the config is per-project (must work for a consumer repo other than NEvo, not
  just this one), the frontend cannot embed it at build time — the server reads the
  project's `changeView`/`generatedFiles` config file from the repository and exposes
  it to the frontend (exact delivery shape is an implementation detail, same as every
  other route in this change — e.g. folded into the task-02 files-manifest response, a
  field on `/api/dashboard`, or a small dedicated config route).

## Constraints

- Depends on D1 (`picomatch`) being added to `tools/dashboard/package.json`.
- Config must be per-project (usable by a consumer repo other than NEvo itself), not
  hardcoded to this repo's layout.

## Interfaces and boundaries

- Consumes: the file manifest from `pull-request-file-and-diff-loading.md`, `picomatch`.
- Exposes: grouped/filtered file view to `changes-panel.tsx`, and a
  hidden-files-are-not-hydrated signal to the background hydration queue.

## Area-specific acceptance criteria

- Given a `changeView.groups` config and a set of file paths, grouping is deterministic
  and first-match-wins (same input always produces the same group assignment).
- A file matching a generated-file rule still appears in its otherwise-matching group
  when generated files are shown, and disappears from the visible list (but not the
  count) when hidden.
- Toggling "hide generated files" never permanently drops those files from the
  available data — toggling back shows them without a fresh fetch of the manifest.
- Background hydration issues zero diff requests for currently-hidden generated files
  until one is explicitly opened.
- Directory and Flat modes require no `changeView.groups` config to function.

## Dependencies

Depends on `pull-request-file-and-diff-loading.md` (needs the file manifest and the
hydration priority/queue mechanism to filter against).

## Out of scope

- Task-to-file provenance / mapping a file to the task that changed it (change-wide
  out-of-scope item — a file may be touched by multiple tasks).
- AI-based or heuristic-beyond-config classification.
